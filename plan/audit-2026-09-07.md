# Backend static audit — 2026-09-07

Scope: `backend/`, `frontend/`, `testing/`, `myll/` library sources and the legacy directories.
The audit only inspected code and documentation; no files were modified.

Summary: the biggest group of findings are dead helpers/extensions and outdated comments that can be removed safely. Several language features are already parsed into the AST but never emitted (properties/accessors, named arguments, null-coalescing calls). A smaller set of items (`Symbol`, `Attribute`, `Map` pointer kinds) are intentional future-design stubs.

## 5. Suggested cleanup order

1. **Safe cleanup** — remove the dead-code items in section 1 and the two legacy directories. This is low risk and removes noise.
2. **Surface hidden features** — implement property/accessor generation and named arguments; both already parse into the AST.
3. **Decide on reserved/future hooks** — keep `Symbol`/`Attribute` and the `Map` pointer kinds, or schedule their removal.
4. **Bigger features** — namespace aliases, contained `using`, `switch` fallthrough modes, range-based `for`.

The fastest wins are the dead-code cleanup and the accessor generation hook, because the parser and AST already support accessors but the generator silently drops them.

## 6. Post-audit changes (2026-09-08)

- Removed the dotted-module-name include branch in `backend/Generator/HierachicalGen.cs`. Myll always generates `{module}.hpp`, so module headers now always emit `#include "module.hpp"`.
- Regenerated all unix apps with `bash frontend/apps/make_unix.sh`. The build succeeded and no generated `.hpp` contains duplicate `#include` lines.
- Confirmed the implicit-standard-import list stays in `backend/Core/StdBuiltins.cs` and the injection logic stays in `frontend/Program.cs`. The backend defines the modules that back built-in constructs; the frontend ties them to the standard-library prototypes shipped with the compiler.
- Extracted the unimplemented-feature list into `plan/todo-unimplemented-2026-09-08.md` for easier tracking.
