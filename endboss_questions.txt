## Current state

Done:
  - Per-module scope trees, instance-based visitors, fixed-point resolver.
  - Cross-module imports including cyclic imports.
  - Qualified static paths (Ns::Inner::Foo, std::helper()).
  - Locals, parameters, lambdas, catch variables, loop index scoping.
  - [hide] / [hidden] export control.
  - Prototype/extern declaration files (.decl.myll), forward declarations,
    and the std/ shim.

Not done:
  - std:: is not a built-in logical module; it only resolves via explicit
    import of std_*.decl.myll shims.
  - using namespace / using Name are parsed but ignored by the resolver.
  - Member access (my.method()) is not resolved.
  - Type checking, overload resolution, and conversions are absent.
  - The C++ generator never consumes ResolutionResult; raw AST names are
    emitted.
  - Access modifiers still use a mutable curAccess hack and string attributes.
  - PickSingle silently drops ambiguous names instead of reporting them.
  - backend/ has ~86 TODO/FIXME/HACK markers and 36 NotImplemented/NotSupported
    throws.

## Definition of done

  1. -R becomes the default (and eventually only) compiler mode.
  2. All names -- including std:: and using-imported names -- resolve or
     produce a clean diagnostic.
  3. Member access resolves via the target's type.
  4. The C++ generator emits resolved, fully-qualified C++ names from the
     resolver rather than raw AST text.
  5. A type checker rejects bad assignments/arguments and enables type-driven
     codegen.
  6. Semantic validation moves out of the generator and into resolver/
     validation passes.
  7. plan/semantic-analysis.md and stale analysis docs are updated.

  [ ] 1.1 Decide and implement std / built-in namespace integration.

### Phase 3 -- Type checking and overload resolution

  [ ] 3.1 Compute and store expression types (AST field or separate type map).
  [ ] 3.2 Validate assignments, return types, call argument counts/types.
  [ ] 3.3 Implement overload resolution from Phase 1 sets + argument types.

          enum base validation.
  [ ] 3.5 Validate new T, casts, null, and implicit conversions.

  Exit criteria:
    - Type errors produce diagnostics; valid code generates correct C++.
    - Overloaded calls resolve to a single target.

### Phase 4 -- Cleanup and model hardening
